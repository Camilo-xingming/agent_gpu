# NVIDIA Blackwell Architecture Analysis for RalphGPU

## Executive Summary

This document analyzes NVIDIA Blackwell's architectural changes and their implications for RalphGPU optimization.

## 1. Key Blackwell Execution Model Changes

### 1.1 Per-Thread vs Warp-Synchronous Execution

**Previous (Volta/Ampere/Hopper):**
- Warp-synchronous MMA via `wgmma` requiring 128 threads (warp-group)
- All 32 threads in a warp must synchronize before MMA operations
- Lock-step model reduced scheduling flexibility

**Blackwell (New):**
- Single-thread `tcgen05.mma` instruction
- Each thread independently issues MMA operations
- **No warp-level synchronization required** for tensor ops
- Enables true per-thread scheduling for tensor operations

### 1.2 Latency Improvements

| Metric | Hopper | Blackwell | Improvement |
|--------|--------|-----------|-------------|
| Single-instruction latency | Variable (scales with tile) | ~11 cycles (constant) | 2.9-11.6× lower |
| Scheduler stalls | Baseline | 18-23% reduction | Memory-bound kernels |

### 1.3 Tensor Memory (TMEM)

Blackwell introduces a dedicated 256KB on-chip memory per SM:
- **Structure:** 512 columns × 128 rows × 32-bit cells
- **Bandwidth:** 16 TB/s read, 8 TB/s write per SM
- **Purpose:** Replaces register-based accumulator storage
- **Persistence:** Intermediate matrix results persist across warp groups

```
TMEM Address Encoding:
[31:16] = Row (0-127)
[15:0]  = Column (0-511)
```

## 2. tcgen05 Instruction Family

### 2.1 Core Instructions

| Instruction | Semantics | Description |
|-------------|-----------|-------------|
| `tcgen05.mma` | Single-thread | MMA operation with SMEM/TMEM operands |
| `tcgen05.ld` | Async | Load from TMEM to registers |
| `tcgen05.st` | Async | Store from registers to TMEM |
| `tcgen05.cp` | Async | Tensor data transfers to/from TMEM |
| `tcgen05.alloc` | Sync | Allocate TMEM columns |
| `tcgen05.dealloc` | Sync | Deallocate TMEM (required before kernel exit) |
| `tcgen05.commit` | Sync | Signal MMA completion via mbarrier |

### 2.2 Instruction Format

```
tcgen05.mma.cta_group.kind [d-tmem], a-desc, b-desc, idesc,
                           { disable-output-lane }, enable-input-d {, scale-input-d};
```

Where:
- `d-tmem`: TMEM address for accumulator
- `a-desc/b-desc`: 64-bit shared memory descriptors
- `idesc`: 32-bit instruction descriptor (data types, MMA shapes, density)

### 2.3 Key Differences from wgmma (Hopper)

| Aspect | wgmma (Hopper) | tcgen05 (Blackwell) |
|--------|----------------|---------------------|
| Data Source | Shared memory | SMEM + TMEM for A |
| Accumulator | Registers | **Tensor Memory** |
| Max BF16 Shape | m64n256k16 | **m128n256k16** |
| Synchronization | Blocking | **Fully asynchronous** |
| Granularity | 128 threads (warp-group) | **32 threads (warp-level)** |

## 3. RalphGPU Required Changes

### 3.1 Currently Implemented (Blackwell-Ready)

RalphGPU already has some Blackwell-inspired features:
- ✅ `blackwell_scheduler.v` with multi-scheduler support (1-4 schedulers)
- ✅ DPX instructions (`OP_DPX` in gpu_defines.vh)
- ✅ Sparse MMA opcodes
- ✅ mbarrier operations (`OP_MBARRIER`)

### 3.2 New Modules Required

1. **tensor_memory.v** - TMEM implementation
   - 256KB storage (512 × 128 × 32-bit)
   - Column allocation tracking
   - High-bandwidth ports

2. **tcgen05_unit.v** - tcgen05 instruction execution
   - Single-thread MMA dispatch
   - SMEM descriptor parsing
   - Async completion signaling

### 3.3 Modified Modules

1. **decoder.v** - Add tcgen05 opcode family
2. **tensor_core.v** - Support async per-thread MMA
3. **blackwell_scheduler.v** - Per-thread tensor op tracking
4. **streaming_multiprocessor_v2.v** - TMEM integration

### 3.4 New Opcodes to Add (gpu_defines.vh)

```verilog
// Blackwell tcgen05 instruction family
`define OP_TCGEN05_MMA      6'b111000   // tcgen05.mma
`define OP_TCGEN05_LD       6'b111001   // tcgen05.ld
`define OP_TCGEN05_ST       6'b111010   // tcgen05.st
`define OP_TCGEN05_CP       6'b111011   // tcgen05.cp
`define OP_TCGEN05_ALLOC    6'b111100   // tcgen05.alloc
`define OP_TCGEN05_DEALLOC  6'b111101   // tcgen05.dealloc
```

## 4. Triton Compilation Path

### 4.1 Compilation Pipeline

```
Python Kernel
     ↓
Triton-IR (Unoptimized, machine-independent)
     ↓
Triton-GPU IR (Optimized for GPU)
     ↓
LLVM-IR
     ↓
PTX Assembly
     ↓
cubin (Binary)
```

### 4.2 PTX Instructions Commonly Generated by Triton

| Category | Instructions | RalphGPU Status |
|----------|--------------|-----------------|
| Memory | ld.global, st.global, ld.shared, st.shared | ✅ Supported |
| Compute | add, mul, fma, div | ✅ Supported |
| Control | bra, setp, @p | ✅ Supported |
| Sync | bar.sync, membar | ✅ Supported |
| Tensor | wmma.mma, mma | ✅ Supported |
| Special | shfl.sync, vote | ✅ Supported |

### 4.3 Gap Analysis

**Well Supported:**
- Basic compute (ALU, FPU, SFU)
- Memory operations (global, shared, local)
- Control flow (branches, barriers)
- Traditional WMMA

**Needs Enhancement:**
- Blackwell tcgen05 instructions (for SM100+ targets)
- TMEM operations
- Per-thread tensor scheduling
